Foldlet 0.10.2 keeps its Recent apps menu visible while closing Samsung tasks.

- **×** and **Close all** keep Foldlet on the cover screen while the existing Samsung Recent action runs underneath. The menu updates when closing finishes, without showing the Samsung transition during the verified flow.
- The active **×** becomes a rotating loading indicator and cannot be tapped repeatedly. On success its card disappears; on failure the normal × returns.
- Task closing still removes the actual Samsung Recent task, rather than only stopping an app while leaving its system history card behind. This is presentation continuity around Samsung's task action, not a new privileged direct task-removal API.
- Uses Android 14's accessibility overlay API with the service already enabled. No extra permission grant, USB connection, root, or Shizuku is needed.
- The temporary layer contains only Foldlet's own menu. It is discarded on completion, timeout, screen-off, locking, unfolding, or stopping the service. If it cannot be prepared, no task action starts.
- Requires Android 14 or newer for task closing. Locked-task and unsupported-launcher rules still follow Samsung.

Verified on a Galaxy Z Flip3 (SM-F711B, Android 14 / One UI 6.1.1): the dedicated test task disappeared from Android's system Recent list, and all sampled frames during the operation retained Foldlet's menu header. Existing user apps were not closed during this verification.

Update **Foldlet-0.10.2.apk** and open Foldlet once. **Foldlet Controls 1.1.0** is unchanged. Both signed, non-debuggable beta APKs and their SHA-256 files are attached.
